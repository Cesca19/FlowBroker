# FlowBroker
 
**A concurrent C++ publish/subscribe server that ingests real-time data streams, routes them by topic, and broadcasts them live to subscribed Qt clients.**
 
FlowBroker is domain-agnostic by design: the server routes messages by topic and never inspects their content, so stock prices, weather readings and sensor telemetry can all flow through the same pipeline. Finance is simply the first source that ships with it.
 
> Built as a systems-programming project, FlowBroker demonstrates a thread-safe producer/consumer pipeline, an asynchronous multi-client TCP server, per-topic sliding-window statistics, and a real-time Qt charting client, on top of a cross-platform CMake/Conan build.

## Technical Highlights
The engineering work behind FlowBroker, at a glance:
- **Domain-agnostic pub/sub broker** : messages travel through a generic `Message` envelope and are routed by topic alone,
  so a new data source plugs in without touching the pipeline
- **Thread-safe producer/consumer** : Thread-safe producer-consumer pattern: data ingestion and processing run in separate threads,
  connected by a queue protected by a mutex and a condition variable, without busy-waiting.
- **Asynchronous multi-client server** : built on Boost.Asio, the server accepts new connections and reads and writes
  on each one without ever blocking, so many clients are served at the same time
- **Per-topic sliding-window statistics** : last value, min, max and average kept over a moving time window
  in an in-memory cache, so a new subscriber is served the current state instantly
- **Simulated finance sources** : six assets generated by geometric Brownian motion, each emitting at its own frequency
- **Cross-platform - **Cross-platform build & release automation** : Conan and CMake custom
  build/clean scripts for Windows and Linux, and a tag-driven GitHub Actions
  pipeline that builds and publishes release archives

<br>

## Features
- **Live simulated streams** : six finance topics (GOLD, S&P, BTC, AAPL, EURUSD, OIL) updating in real time
- **Real-time charts** : the Qt client draws one live line chart per topic, created dynamically as topics appear
- **Multi-client** : several clients can connect at once and receive the same live broadcast
- **Per-topic statistics** : last value, min, max and average, refreshed every second

<br>

## Architecture
The server's workflow revolves around four stages. First, data sources feed a thread-safe queue. From there, a consumer
drains the queue and updates a per-topic cache. That cache is then read by an asynchronous TCP layer, which broadcasts 
a snapshot of every topic once per second to the connected clients. In short, the data flows like 
this: sources → data queue → consumer → topic cache → TCP broadcast → Qt clients.

## Build from source
Dependencies (Boost, Qt) are resolved by Conan. The provided scripts bootstrap the toolchain 
(check Python/CMake, install Conan locally, resolve dependencies, configure CMake and build).
Binaries are placed in `bin/`.

### Prerequisites
- A C++17 compiler (GCC on Linux, MSVC on Windows)
- Python 3.7+ and CMake 3.28+
- Conan is installed automatically by the scripts if missing

### Linux
```bash
# Usage: ./scripts/build_linux.sh [BUILD_TYPE] [RUNTIME_LINK]
# BUILD_TYPE   = Debug | Release    (default: Debug)
# RUNTIME_LINK = static | dynamic   (default: dynamic)
 
chmod +x ./scripts/build_linux.sh
./scripts/build_linux.sh Release static
```
 
### Windows
```bat
@REM Usage: build_windows.bat [BUILD_TYPE] [RUNTIME_LINK]
scripts\build_windows.bat Release dynamic
```
 
### Run
Start the server on a TCP port, then connect one or more clients:
```bash
./bin/flow_broker_server 4242            # server: listens on the given port
./bin/flow_broker_client 127.0.0.1 4242  # client: connects to host and port
```
Launch several clients against the same server to see the multi-client broadcast.
 
To clean build artifacts: `scripts\clean_windows.bat` / `./scripts/clean_linux.sh`.
